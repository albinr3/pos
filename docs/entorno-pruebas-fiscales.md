## Configuración y arranque

1. Instalar PostgreSQL y dependencias del proyecto. Con `.env` local que apunte a PostgreSQL local y claves Clerk de desarrollo, ejecutar `npm run fiscal-test:init` una sola vez. Crea `.env.fiscal-test` sin sobrescribirlo; contiene credenciales y un PIN de prueba. No compartirlo ni subirlo a Git.
2. Preferir dos identidades ficticias de Clerk de desarrollo, sin datos reales. Colocar sus identificadores distintos `user_...` en `FISCAL_TEST_CLERK_USER_A` y `FISCAL_TEST_CLERK_USER_B`. La consulta con clave de producción exige autorización expresa y la opción indicada arriba. Consultar el PIN en `FISCAL_TEST_PIN` localmente. No enviar claves ni PIN por chat.
3. La base activa ya está preparada. Los comandos `fiscal-test:create`, `fiscal-test:setup` y `fiscal-test:constraints` crean una base con el esquema Prisma y reglas adicionales, pero **no reproducen por sí solos** el orden de enums, las políticas ni los permisos de la captura de producción; no usarlos como una réplica equivalente sin completar y verificar esos elementos.
4. Ejecutar `npm run fiscal-test:seed`. Verifica ambas identidades mediante la API de Clerk y solo inserta datos si la base no contiene empresas. Crea dos empresas, cada una con `dueno` y `cajero`, cliente general, cliente a crédito, proveedor y producto. El mismo PIN local sirve para ambos usuarios de prueba. No crea ventas ni saldos: se deben generar en los escenarios de prueba.
5. Ejecutar `npm run fiscal-test:check`. El comando `npm run fiscal-test:dev` permanece bloqueado hasta implementar y comprobar el aislamiento de salidas externas; todavía no se debe iniciar la interfaz con esta configuración.

La instancia local no se instaló como servicio del sistema. Para iniciarla tras reiniciar el equipo, ejecutar `npm run fiscal-test:db:start`; para comprobar su estado, `npm run fiscal-test:db:status`; para detenerla, `npm run fiscal-test:db:stop`. Se han verificado la detención y el reinicio. Los binarios, el directorio de datos, la copia temporal del esquema y los respaldos están en `tmp/`: no borrar esa carpeta mientras se necesite el entorno. La conexión y la contraseña locales se guardan en `.env.fiscal-test` y `.env.fiscal-pg17`; no compartirlos.

Para una base nueva, modificar únicamente el nombre en `TEST_DATABASE_URL` por `movopos_fiscal_test_<número>` y repetir creación y preparación. Nunca ejecutar estos scripts con la base del negocio. Los preparadores de las suites de caja y compras tienen requisitos de nombre propios y necesitan otras bases vacías; no apuntarlos a esta base.
